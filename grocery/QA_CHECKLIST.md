## Admin Edge Function API (QA source only)
Function: `friendride-grocery-admin` (POST JSON; JWT required)

Supported actions:
- `list_applications`
- `decide_application` with `application_id` and status `approved`, `rejected`, or `on_hold`
- `get_links`
- `update_links` with HTTPS issuer URLs

Security expectations:
1. Missing/invalid JWT must return 401.
2. Authenticated user absent from `public.admin_users` must return 403.
3. Only the single existing Primary Admin allow-list record is authorized; no alternate account is provisioned.
4. Admin mutations use service-role credentials only inside the Edge Function. Never expose the service-role key in browser code.
5. Application status and issuer links are not directly writable by browser clients.
6. Congratulations is allowed only when the trusted backend response returns `application_status = approved`.
7. FRIEND RIDE operational approval is not a bank credit/card/EMI approval.

Required QA environment secrets (never paste values into chat or commit them):
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
